# 07-lessons: record what was learned, so the next session applies it

Stage map: [README.md](README.md). `easel next` does not route here; a request does (the routing table of
[AGENTS.md](../../AGENTS.md)). What a lesson is, and how one is contributed back:
[docs/lessons/README.md](../lessons/README.md).

## 1. Purpose and who decides

A lesson is one finding, the evidence for it and the rule it implies. A verdict says what happened to one
image; a lesson says what to do next time, so a later session, or a weaker model, applies it without learning
it again. Lessons are appended to `<home>/lessons/entries.jsonl` and rendered into one page per family.

- **The operator decides** what counts as a lesson and its wording. Feedback they read on a model page is
  theirs to copy in.
- **You:** record the operator's words with their evidence, render the pages, and report. A finding of your
  own is stored only with `--assistant`, under the second source (`policy.second_source_name`), and never
  stands for the operator.

## 2. Entry conditions

| command | literal line |
|---|---|
| `easel doctor` | `config: easel.toml (found by <how>) ... ok` |
| `easel lessons list` | `<n> lessons` |

You are here because the operator stated a lesson, or a runbook's gate asks for one (for example
[04-review-and-learn.md](04-review-and-learn.md)). With one lesson the last line reads `1 lesson`. A step
marked planned is not built: report it once and stop at that stage.

## 3. Commands

Read first; `add` appends; `render` writes the pages.

```
easel lessons list --family <family>
easel lessons add --family <family> --finding "<finding>" --evidence "<evidence>" --rule "<rule>" --source review
easel lessons add --finding "<finding>" --evidence "<evidence>" --rule "<rule>" --source civitai
easel lessons render
easel lessons list
```

- `--finding` is what was found, in one sentence; `--evidence` is what shows it (run ids, output numbers,
  counts, dates); `--rule` is what to do from now on. Leave `--family` out for a lesson that holds for every
  family.
- `--source` says where the finding came from: `review` (verdicts), `run`, `search`, `manual` (the default)
  or `civitai` for feedback the operator copied from a model page by hand. No tool reads comments
  ([civitai-rules.md](../reference/civitai-rules.md)).
- `--recorded-in <file>` names the runbook or doc row the lesson also went into, when the same finding became
  a failure-table row.
- A lesson is never edited or deleted. A correction is a new lesson whose evidence names the one it corrects.
- `render` writes `<family>.md` per family and `general.md` for lessons without a family into
  `<home>/lessons/` (`--out <dir>` elsewhere). Each page carries a "generated, do not edit" marker; a page
  without that marker is never overwritten.

## 4. Expected output

`easel lessons list` on the demo:

```
les-20300101-001 | illustrious | review | Start the demo_robot LoRA at 0.8 on Illustrious checkpoints.
1 lesson
```

`easel lessons add --family illustrious --finding "<finding>" --evidence "<evidence>" --rule "<rule>" --source review`:

```
les-20300101-002 added to lessons/entries.jsonl (family illustrious, source review, recorded by operator)
next: easel lessons render
```

`easel lessons render`, twice:

```
wrote lessons/illustrious.md
1 page: 1 written, 0 unchanged, 0 refused
```

```
unchanged lessons/illustrious.md
1 page: 0 written, 1 unchanged, 0 refused
```

Match the shape, not the numbers (see [README.md](README.md)).

## 5. Gate and operator question

1. `easel lessons list` shows the new lesson with the operator's words.
2. `easel lessons render` printed `0 refused`.

Ask once, before `add`, then wait:

> I would record this lesson for `<family or "every family">`: finding "`<finding>`", evidence
> "`<evidence>`", rule "`<rule>`". Is that how you want it worded?

## 6. Symptom, cause, action

| symptom | cause | action |
|---|---|---|
| `refused: <page> was not generated by easel lessons render; ...` | a hand-written page sits where a generated page would go | expected: hand-written pages are never replaced; render into another folder with `--out <dir>` or tell the operator |
| the finding is your own reading, not the operator's words | the operator did not state it | record it only with `--assistant`, or ask the operator first |
| a lesson's wording is wrong | lessons are never edited | add a new lesson whose evidence names the one it corrects |
| the operator quotes feedback from a public post | no tool reads comments | `--source civitai`, in the operator's words |
| a lesson names a subject, an id or a path that must not leave the machine | the page will be shared | before contributing a page back, `easel privacy scan --public <dir>`; fix the wording with a new lesson |

Not in the table: follow [docs/STUCK.md](../STUCK.md).

## 7. Record

```
easel journal note "07-lessons: added <les-id> for <family>; pages rendered"
```

A new pitfall: add a row to the table in section 6, dated from `date`, and a journal line, in the same session.
Stuck: `easel journal stuck "<one line>"`, then [docs/STUCK.md](../STUCK.md).
